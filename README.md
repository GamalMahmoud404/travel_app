# رحلتي — Rehlaty

تنفيذ Next.js (App Router) لتصميم منصة **رحلتي** لحجز الرحلات والسفر
(تصميم: Ahmed Mohamed Abdellhady — [Behance](https://www.behance.net/gallery/255040735/Rehlaty-Travel-Tourism-Booking-Platform)).

الواجهة عربية بالكامل باتجاه RTL، بخط **Cairo**، وبنظام التصميم الأصلي:

| الدور | اللون |
| --- | --- |
| Primary | `#0D2B45` |
| Secondary | `#1CA6A6` |
| Text | `#0F172A` |
| Background | `#F8FAFC` |
| Paragraph | `#475569` |

البيانات مخزّنة في **MongoDB Atlas** ويُقرأ منها عبر **Prisma**.

## النشر

المشروع يقرأ كل محتواه من القاعدة **وقت البناء** (صفحات ISR)، فمنصّة النشر
تحتاج قبل أول بناء:

1. المتغيّرين `DATABASE_URL` و`AUTH_SECRET` في إعدادات المشروع، مفعّلين لبيئة
   الإنتاج — المتغيّرات تُقرأ في بناء جديد لا في نشر موجود.
2. سماح **Network Access** في Atlas لعنوان آلة البناء. عناوين المنصّات بلا
   خادم متغيّرة، فتحتاج `0.0.0.0/0`.

بلا الأول يتوقّف `npm run build` في ثانيته الأولى برسالة تقول أي متغيّر ناقص
(`prisma/check-env.mjs`)، وبلا الثاني يسقط عند توليد الصفحات بمهلة اتصال.

## الإعداد

```bash
npm install
cp .env.example .env      # ثم املأ DATABASE_URL و AUTH_SECRET
                          # AUTH_SECRET مطلوب — بدونه يرمي التطبيق عند أول جلسة:
                          # node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
npm run db:generate       # توليد عميل Prisma
npm run db:push           # مزامنة الـ schema مع القاعدة
npm run db:seed           # زرع محتوى التصميم
npm run dev
```

ثم افتح <http://localhost:3000>.

### أوامر قاعدة البيانات

| الأمر | الوظيفة |
| --- | --- |
| `npm run db:generate` | توليد `@prisma/client` من `prisma/schema.prisma` |
| `npm run db:push` | مزامنة الـ schema مع MongoDB (لا migrations في مونجو) |
| `npm run db:seed` | زرع البيانات من `prisma/seed-data.json` (يرفض التنفيذ إذا كانت القاعدة ممتلئة) |
| `npm run db:seed -- --force` | حذف المجموعات وإعادة الزرع |
| `npm run db:studio` | Prisma Studio لتحرير البيانات |

## البنية

```
prisma/
  schema.prisma       21 مجموعة في MongoDB:
                      • بيانات المجال: Hotel, Room, Activity, Car, Guide, Package,
                        TrendingTrip, Booking, Favorite, Review, User
                      • محتوى الواجهة: SiteSetting, SearchTab, SectionCopy,
                        PaymentMethod, BookingTab, FavoriteFilter, AccountNavItem,
                        SortOption, AboutPage, CheckoutDraft
  seed-data.json      كل المحتوى كبيانات
  seed.mjs            سكربت الزرع
app/
  layout.jsx          الهيكل العام + خط Cairo + dir="rtl"
  globals.css         نظام التصميم بالكامل (متغيرات، مكوّنات، responsive)
  lib/
    prisma.js         عميل Prisma (singleton)
    queries.js        كل استعلامات القراءة — لا يوجد ملف محتوى ثابت
  components/         مكوّنات عرض تستقبل محتواها كـ props
```

**كل ما يظهر على الشاشة يُقرأ من القاعدة**: الفنادق والغرف والأنشطة والسيارات
والمرشدون والباقات والحجوزات والمفضلة والآراء والمستخدم، وكذلك اسم الموقع
وبيانات التواصل وروابط التنقل والتذييل وحسابات التواصل الاجتماعي وصورة ونصوص
الهيرو وتبويبات البحث وحقولها وعناوين كل الأقسام وعناوين التابات (`<title>`)
وطرق الدفع وفلاتر المفضلة وتبويبات الحجوزات وخيارات الترتيب وقائمة الحساب
وألقاب المسافرين وسياسة الإلغاء وخطوات الحجز.

يبقى في الكود نصوص الواجهة الصغيرة فقط: تسميات الأزرار (`عرض التفاصيل`،
`احجز الآن`)، تسميات حقول النماذج، النصوص البديلة (placeholders)، `aria-label`،
رمز العملة، وصفحة 404.

الصفحات كلها `dynamic = 'force-dynamic'` لتعرض البيانات الحالية دائمًا. لا يوجد
أي احتياط ملفّي: إن تعذّر الاتصال بالقاعدة تفشل الصفحة بخطأ واضح.

## الحسابات والصلاحيات

المصادقة مبنية بلا مكتبات خارجية: كلمات المرور بـ `scrypt`، والجلسة كوكي
`httpOnly` موقَّع بـ HMAC-SHA256 من `AUTH_SECRET` (صلاحية 30 يومًا).

**لا توجد حسابات في بيانات الزرع** — سجّل حسابك من `/register`. أول حساب يُنشأ
في قاعدة فارغة يأخذ صفة `admin` تلقائيًا حتى تكون لوحة التحكم قابلة للوصول.

```bash
npm run db:role                          # عرض الحسابات وصفاتها
npm run db:role -- you@mail.com admin    # ترقية
npm run db:role -- you@mail.com user     # تخفيض
```

### الأدوار والصلاحيات

الأدوار في مجموعة `Role` وكل دور يحمل مفاتيح من مجموعة `Permission` — فتعديل
ما يستطيعه دور هو تعديل مستند في القاعدة، بلا نشر جديد.

| الصلاحية | أدمن | مستخدم |
| --- | :-: | :-: |
| `content.read` — تصفّح المحتوى والحجز | ✓ | ✓ |
| `content.write` — إدارة المحتوى والأسعار | ✓ | — |
| `bookings.own` — إدارة حجوزاته ومفضلته ووسائل دفعه | ✓ | ✓ |
| `bookings.all` — الاطلاع على حجوزات الجميع | ✓ | — |
| `users.read` — عرض المستخدمين | ✓ | — |
| `users.write` — تغيير الصفات | ✓ | — |
| `admin.access` — الدخول إلى لوحة التحكم | ✓ | — |

الحماية في [app/lib/permissions.js](app/lib/permissions.js):

- `requirePermission(key, returnTo)` — غير المسجَّل يُحوَّل إلى `/login?next=…`،
  والمسجَّل بلا صلاحية يرى **404** (لا نكشف وجود الصفحة).
- عناصر قائمة الحساب مقيَّدة بحقل `requires` في `AccountNavItem` — «لوحة التحكم»
  تظهر فقط لمن يملك `admin.access`.
- تغيير الصفات في `/admin` يحتاج `users.write`، ولا يستطيع أحد تغيير صفة نفسه،
  ولا تخفيض آخر أدمن في الموقع.

| المسار | الصلاحية المطلوبة |
| --- | --- |
| `/account`, `/account/favorites`, `/account/payments`, `/account/notifications` | `bookings.own` |
| `/bookings`, `/booking/travelers`, `/booking/payment` | `bookings.own` |
| `/admin` | `admin.access` |

العامة بلا جلسة: `/`, `/hotels`, `/hotels/[slug]`, `/offers`, `/reviews`,
`/about`, `/login`, `/register`.

### وسائل الدفع والإشعارات

- `/account/payments` — البطاقات المحفوظة: إضافة، تحديد الافتراضية، حذف.
  **لا يُخزَّن رقم البطاقة الكامل ولا CVV** — فقط النوع وآخر 4 أرقام والاسم
  وتاريخ الانتهاء. عند حذف الافتراضية تنتقل الصفة لأقدم بطاقة متبقية.
- `/account/notifications` — صندوق الإشعارات (تعليم الكل كمقروء، حذف) +
  تفضيلات القنوات والمواضيع. القيم في `User.notifyOff` وتعريفاتها في
  `NotificationSetting`.
- الصورة الشخصية: تُختار في `/register` وتُعدَّل في `/account` — تُقصّ مربعًا
  وتُصغَّر إلى 256×256 في المتصفح ثم تُخزَّن data URL (~5–30KB)، ويتحقق الخادم
  من النوع والحجم (حد 400KB).

> `npm run db:seed -- --force` يعيد زرع المحتوى فقط. لا يُنشئ حسابات ولا يحذف
> حسابًا مسجَّلًا ولا بياناته. لمعاينة شاشات حجوزاتي/المفضلة ممتلئة:
> `npm run db:seed -- --force --demo you@mail.com`

### عند تعذّر الوصول إلى Atlas

إن رفضت الشبكة الاتصال (`Server selection timeout` أو `TLSV1_ALERT_INTERNAL_ERROR`):

- **الموقع يبقى يعمل** — الصفحات العامة ثابتة (ISR)، فتُخدَم النسخة الأخيرة
  المبنية بدل الانهيار.
- **لا يُفقد شيء** — المحتوى كله في `seed-data.json`. أعد الزرع عند استقرار الشبكة:

```bash
npm run db:seed -- --force
```

- الزرع يعمل داخل **معاملة واحدة**، فانقطاع الشبكة في منتصفه يُلغي الكتابة
  ويُبقي المحتوى القديم سليمًا.

## الوضع المظلم

زر التبديل في شريط التنقّل ([ThemeToggle](app/components/ThemeToggle.jsx)) بثلاث حالات فعلية:

- **بلا اختيار** → يتبع تفضيل النظام (`prefers-color-scheme`)، ويتغيّر معه فورًا.
- **اختيار يدوي** → يُحفظ في `localStorage` ويتجاوز تفضيل النظام.

لا وميض عند التحميل: سكربت `beforeInteractive` يضع `data-theme` على `<html>`
قبل أول رسم، و`<html>` عليها `suppressHydrationWarning` لأن الخادم لا يعرف
تفضيل المتصفح.

### كيف بُني

الألوان كلها رموز في `:root`، فالوضع المظلم إعادة تعريف للطبقة وحدها — لا نسخ
قواعد ولا `!important`:

```
:root                                  → الفاتح
@media (prefers-color-scheme: dark)
  :root:not([data-theme="light"])      → المظلم تلقائيًا
:root[data-theme="dark"]               → المظلم باختيار المستخدم
```

| الرمز | فاتح | مظلم |
| --- | --- | --- |
| `--bg` | `#f8fafc` | `#0a1520` |
| `--white` (السطح) | `#ffffff` | `#0f1f2e` |
| `--text` | `#0f172a` | `#e9f0f7` |
| `--border` | `#e4e9f0` | `#1d3345` |
| `--primary` | `#0d2b45` | `#1e5382` |
| `--secondary` | `#1ca6a6` | `#2cc0c0` |
| `--footer-bg` | `#0d2b45` | `#071019` |

قرارات تستحق الذكر:

- **الدرجات الدلالية ثابتة** (نجاح/خطر/تحذير) كي لا يتغيّر تباين الشرائح
  الملوّنة؛ المقلوب هو خلفياتها الخفيفة (`--*-050`) وحدودها ونصوصها.
- رمز `--on-teal` أُضيف لأن الأبيض على الأخضر المائي الأفتح في الوضع المظلم
  تباينه ضعيف — فصار النص غامقًا هناك.
- `--footer-bg` رمز منفصل عن `--primary`، وإلا صار التذييل أفتح من الصفحة.
- سهم القوائم المنسدلة مضمَّن في `data:` URI فلا يقرأ المتغيّرات — له قاعدة
  خاصة بلون فاتح في الوضع المظلم.
- `color-scheme` مضبوط في الوضعين فتتبع عناصر المتصفح (شرائط التمرير،
  حقول التاريخ) الوضع الصحيح.
- الهيرو يبقى غامقًا في الوضعين لأنه صورة بتعمية — وهو المقصود.

## الأداء

كل ذهاب وعودة إلى Atlas ≈ **200ms**، وكانت الصفحات تُصدر عشرات الاستعلامات في
كل طلب. ما تم:

| المشكلة | المعالجة |
| --- | --- |
| المحتوى المشترك يُقرأ من القاعدة في كل طلب | `unstable_cache` بوسم `content` و TTL 5 دقائق في [queries.js](app/lib/queries.js) |
| `getSessionUser` يتكرّر بين layout والصفحة والحارس | `cache()` من React — استعلام واحد لكل طلب |
| قراءة الدور والصلاحيات في كل حارس | مخزَّنة بوسم `rbac` |
| لوحة التحكم: 11 عدّة متسلسلة (≈ 2.2s) | `Promise.all` — موجة واحدة |
| خط Cairo من Google (3 ذهاب وعودة قبل الرسم) | `next/font/google` — مستضاف محليًا |
| البطاقة تُعرض بـ 360px وتنزّل صورة 900px | `npm run db:images` يضبط مقاسات Unsplash |

النتيجة على نفس الجهاز والشبكة:

```
الرئيسية      1.35s  →  0.17s   (‎8×‎)
بقية الصفحات  0.40s  →  0.15s   (‎2.7×‎)
صور أول شاشة  629KB  →  226KB   (‎-64%‎)
```

### تنبيه مهم عن المخزَّن

المحتوى مخزَّن 5 دقائق، فتعديلك المباشر في القاعدة **لن يظهر فورًا**. لتحديثه:

- زر **«تحديث مخزَّن المحتوى»** في `/admin` (يحتاج `content.write`)، أو
- انتظر انتهاء الـ TTL، أو
- في التطوير: أوقف الخادم واحذف `.next/cache` ثم أعد التشغيل.

الصفوف الخاصة بمستخدم (الحجوزات، المفضلة، البطاقات، الإشعارات) **لا تُخزَّن
أبدًا** — تُقرأ طازجة في كل طلب، والـ Server Actions تستدعي `revalidatePath`.

```bash
npm run db:images            # عرض ما سيتغيّر من مقاسات الصور
npm run db:images -- --apply # تطبيقه على القاعدة و seed-data
```

## الاختبارات

```bash
npm test        # منطق نقي بلا قاعدة بيانات (node:test — بلا تبعيات)
```

يغطّي [tests/logic.test.mjs](tests/logic.test.mjs):

- **الصورة الشخصية** ([images.js](app/lib/images.js)): الصيغ المقبولة، رفض
  `svg` و`text/html` و`javascript:` و`http`، وحدّ الحجم عند 400KB.
- **كلمات المرور** ([password.js](app/lib/password.js)): صيغة
  `scrypt$salt$hash`، ملح مختلف لكل تعمية، الحساسية لحالة الأحرف، وعدم رمي
  استثناء عند المدخلات التالفة.

تعمية كلمات المرور في وحدة `password.js` نقية بلا اعتماد على Next، فتُستورد
من الخادم ومن الاختبارات معًا.
